    <h2>The Idea</h2>
    <p>
      Many servers don’t need to be powered on 24/7 to fulfill their purpose. In my home lab, I have a primary server that serves my data and another dedicated to backups. The backup process takes about 20 minutes daily, yet the server remains off most of the time to save power. My challenge was: how can I automatically start the backup server, run the process, and shut it down when finished? Taking this further, I wanted a general solution, something that could trigger any process on any remote server, powering it up only when needed and shutting it down once idle.

<CollapsibleSection title="Features" emoji="📋">

- The calling server can wake another server on the local network and be notified when that server is ready to accept jobs.
- The solution will be able to run jobs on any server on the local network, or on the calling server.
- There will be a UI which shows jobs run/running and schedule of jobs to be triggered. This will be hosted on single a dedicated server.
- When all jobs are completed on a server, it is shutdown to save power.
- Logs of jobs run/running will be kept. These logs can be used in the UI.

</CollapsibleSection>
